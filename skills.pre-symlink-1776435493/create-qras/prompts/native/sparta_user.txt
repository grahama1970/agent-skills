## INVALID OUTPUT EXAMPLES

### Invalid Example 1: Duplicate aspect coverage
{{
  "pairs": [
    {{
      "question": "What is SV-AC-1?",
      "pair_type": "countermeasure_description",
      "answer": "..."
    }},
    {{
      "question": "How does SV-AC-1 work?",
      "pair_type": "countermeasure_description",
      "answer": "..."
    }}
  ],
  "skipped_reason": null
}}
WHY INVALID:
Both pairs cover the same aspect. Definition and mechanism belong in one countermeasure_description pair.

### Invalid Example 2: Invented NIST relationship
{{
  "pairs": [
    {{
      "answer": "SV-AC-1 is derived from NIST SP 800-53 AC-2 Account Management."
    }}
  ],
  "skipped_reason": null
}}
WHY INVALID:
The source does not explicitly state any NIST mapping in the description field.

### Invalid Example 3: Ungrounded explanatory context
{{
  "pairs": [
    {{
      "answer": "Access control is essential for protecting spacecraft from cyber attacks that could disrupt mission operations."
    }}
  ],
  "skipped_reason": null
}}
WHY INVALID:
That explanatory sentence is not present in the admissible source fields.

### Invalid Example 4: Inferred implementation advice
{{
  "pairs": [
    {{
      "pair_type": "implementation_guidance",
      "answer": "Organizations should implement role-based access control using LDAP and hardware security modules."
    }}
  ],
  "skipped_reason": null

WHY INVALID:
The description does not explicitly mention LDAP or hardware security modules.

### Invalid Example 5: Strengthened modality
{{
  "pairs": [
    {{
      "source": "should implement access controls",
      "answer": "must implement access controls"
    }}
  ],
  "skipped_reason": null
}}
WHY INVALID:
The answer strengthens "should" (recommendation) to "must" (requirement).
