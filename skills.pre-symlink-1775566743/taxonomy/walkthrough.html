/extract-entities + /taxonomy

Sentence in, entities and Mind tags out. Here's exactly what to call and what you get back.

1. TL;DR — The Full Pipeline in 30 Seconds

flowchart LR Q["'How does CWE-119\naffect REC-0001?'"] EE["/extract-entities"] IDS["control_ids:\nCWE-119, REC-0001\nST0001"] TAX["/taxonomy"] MIND["mind:\nExploit, Harden, Model"] Q --> EE --> IDS --> TAX --> MIND style EE fill:#d4edda,stroke:#28a745,color:#000 style TAX fill:#cce5ff,stroke:#004085,color:#000
You send 
A sentence (natural language question or claim)
You get back 
/extract-entities → control_ids, resolution_map, grounding_ok
/taxonomy         → mind tags, heart tags, method
Design principles:
  • No regex — flashtext (Aho-Corasick) matches against the actual ArangoDB vocabulary
  • /memory daemon httpx — primary DB access path. Inside the memory project, AQL is allowed as a fallback when the daemon is unavailable (e.g. tests).
  • Deterministic first — Sensai Cascade: T0 lookup (fast), T0.5 classifier (only ≥95%, clamped — cannot be lowered), T2 LLM (grey zone only)

3. /taxonomy — What You Call and What You Get

CLI

# With pre-extracted control IDs (preferred)
./run.sh extract -t "buffer overflow reconnaissance" --control-ids "CWE-119,REC-0001" --fast

# Without control IDs (classifier/LLM only, no Tier 0)
./run.sh extract -t "some security text" -c sparta --fast

Python

from taxonomy import extract_taxonomy

result = extract_taxonomy(
    text="buffer overflow reconnaissance",
    collection="sparta",
    fast=True,
    control_ids=["CWE-119", "REC-0001"],  # from /extract-entities
)
print(result["mind"])    # ["Exploit", "Harden", "Model"]
print(result["heart"])   # []
print(result["method"])  # "fast+refs"

Where do the mind tags come from?

/taxonomy reads the mind field already stored on each control document in sparta_controls. These were pre-computed at ingestion time by the SPARTA pipeline traversing the CWE → CAPEC → ATT&CK chain. At query time, it's just a document lookup — no chain traversal.

# What /taxonomy does internally for each control_id:
POST /list → {collection: "sparta_controls", filters: {control_id: "CWE-119"}}
# Response: {mind: ["Exploit", "Harden"], capec_ids: [...], pillar_cwe: "CWE-664"}
# → takes the mind field, adds to tag set

5. How /extract-entities Works Internally

You don't need to know this to use the skill — but here's what happens under the hood.

1

flashtext Aho-Corasick scan

A KeywordProcessor loaded with 17,792 keywords (both control IDs and names) from sparta_controls via /memory daemon POST /list. Scans text in O(n). Matches "CWE-119" by ID or "SQL Injection" by name — both resolve to the same control_id.

2

RapidFuzz fallback

If flashtext finds nothing, fuzzy matching catches typos: "CWE-7" → "CWE-79" (score 80+).

3

Verify via /memory daemon

POST /list confirms each match exists, gets metadata (name, framework, QRA count).

4

Hybrid search (BM25 + semantic)

Finds related controls not mentioned by name. Catches implicit references.

5

Spellcheck + corpus membership

Classifies remaining terms: domain vocab, misspelling, fabricated ID, or not in corpus.

6. The Sensai Cascade (/taxonomy tiers)

flowchart TD START["extract_taxonomy(text, control_ids)"] --> T0{"T0: control_ids\nprovided?"} T0 --> |"Yes"| T0_LOOKUP["Look up mind from\nsparta_controls via\n/memory daemon\n~5ms per ID"] T0 --> |"No"| T0_SKIP["ref_mind = empty"] T0_LOOKUP --> T0_RESULT["ref_mind = set union\nof all control mind tags"] T0_SKIP --> FAST T0_RESULT --> FAST{"fast mode?"} FAST --> |"Yes"| DONE["Return ref_mind\nmethod: fast+refs"] FAST --> |"No"| CLF{"T0.5: Classifier\nconfidence >= 95%?"} CLF --> |"Yes: merge"| CLF_MERGE["mind = ref_mind UNION\nclassifier tags"] CLF --> |"No: IGNORED"| LLM["T2: LLM grey zone\n/scillm Claude Sonnet"] LLM --> LLM_MERGE["mind = ref_mind UNION\nLLM tags"] CLF_MERGE --> HEART["Heart: keyword scan"] LLM_MERGE --> HEART DONE --> HEART HEART --> FINAL["Return: mind, heart,\nmethod, confidence"] style T0 fill:#d4edda,stroke:#28a745,color:#000 style T0_LOOKUP fill:#d4edda,stroke:#28a745,color:#000 style CLF fill:#fff3cd,stroke:#ffc107,color:#000 style LLM fill:#f8d7da,stroke:#dc3545,color:#000 style HEART fill:#e2d5f1,stroke:#7b2d8e,color:#000 style DONE fill:#d4edda,stroke:#28a745,color:#000 style FINAL fill:#cce5ff,stroke:#004085,color:#000
TierWhatWhenCost
T0Control ID lookup via /memory daemonAlways (when control_ids provided)~5ms per ID
T0.5DistilBERT classifierOnly if confidence ≥ 95%~3ms, free
T2LLM via /scillm (Claude Sonnet)Grey zone only (T0 + T0.5 insufficient)~2s, API cost
HeartKeyword scan for emotionAlways~0ms
Key rule: Below 95% confidence, the classifier is fully ignored — its tags never appear in the output. Only T0 deterministic lookups and T2 LLM contribute. This prevents low-confidence guesses from polluting the tag set.
