# Dogpile Report: fix common violations in Python project: handwritten-tests(71)

## Codex Technical Overview
`handwritten-tests(71)` is usually a smell category: many tests are manually authored in repetitive, brittle patterns rather than generated from shared contracts/fixtures.

**What this usually means architecturally**
- Tests are coupled to implementation details instead of behavior contracts.
- Per-test setup is duplicated instead of using layered fixtures/factories.
- Assertions are narrow snapshots of exact structure/string output, causing churn.
- Mock-heavy unit tests replace runtime sanity checks, so regressions slip through.

**Internal-style patterns to adopt (Python)**
- Contract-first test modules: one behavioral spec drives many cases.
- Parametrized matrices (`pytest.mark.parametrize`) for variants, not copy-paste tests.
- Non-mocked sanity tests alongside unit tests (explicit house rule): test real IO boundaries in a small happy-path suite.
- Function-first seams: keep business logic pure; integration edges are thin and testable.
- Stable test data builders/factories with explicit defaults, not ad hoc dicts in each test.

**Common pitfalls in “fix 71 violations” efforts**
- Mechanical rewrite only (format change, no semantic improvement).
- Over-mocking external boundaries and never validating real protocol assumptions.
- Keeping assertions too specific (field order, formatting noise) instead of invariants.
- Migrating to parametrization without improving failure diagnostics (unclear case IDs).
- Not introducing coverage for failure modes and idempotency/retry behavior.

**State-of-the-art approach**
1. Classify violations by pattern (duplication, brittle assertions, mock abuse, setup sprawl).
2. Create reusable test primitives first: factories, fixtures, assertion helpers.
3. Convert repeated tests to parameterized/property-based forms (Hypothesis where useful).
4. Add a thin sanity lane (real dependencies, minimal dataset, CI-gated).
5. Enforce with tooling: lint rules for test anti-patterns, mutation testing for test strength, flaky-test quarantine + retry telemetry.
6. Track quality metrics beyond coverage: mutation score, flaky rate, median failure triage time.

**Practical target outcome for `handwritten-tests(71)`**
- 30-50% fewer LOC in tests.
- Higher signal per failure (named parameter cases, invariant-focused assertions).
- Fewer false positives on refactors.
- Better regression catch rate via combined unit + non-mocked sanity suites.
