# Shame evaluation scope

One canonical catalog: `agentic_eval.json`. The extension catalog is a symlink,
not a second suite. Use the existing runner's `--case NAME` for a focused run;
`sanity.sh` delegates to this catalog. Run it once, not through every alias.

## Evidence, not a pass count

The suite exercises real Pi conversations, tool execution, CLI operations,
filesystem effects, and Memory. Faults modify real runtime messages before the
production guard sees them; they do not replace Pi with a mocked callback registry.
Every capability requires its declared live evidence class. Each workflow runs
twice and reads back the produced artifacts independently. Local assertions are
the oracles, not fake output generated by the code under test. Feedback uses an
explicitly synthetic label on a real captured turn, not a human quality judgment.

| Workflow | Required effect |
|---|---|
| advisory-question | one answer, no tools or report loop |
| single-format-correction | real work followed by one tool-free footer correction |
| work-continues-to-artifact | repeated continuation reaches a correct artifact |
| invalid-proof-recovery | unresolved proof rejected, journaled, corrected |
| duplicate-key-recovery | duplicate data refused through the real conversation |
| missing-verification-recovery | incomplete done data refused and corrected |
| data-not-prose-decides | misleading prose cannot override valid status data |
| task-scope-and-acceptance | injected out-of-scope tool calls denied; task still finishes |
| feedback-and-session-isolation | independent sessions, capture CLI, Memory store/recall |
| audio-install-preserves-reference | actual reference installed; bad replacement refused |

## Removed rather than relabeled

The old 119-case catalog included 84 calls to one prose-variation probe. That
probe retained obsolete rejection names while rewriting many expectations to
`pass`. It also wrote fabricated `/tmp/proof*` files. Both catalog duplication
and that probe have been removed.

Direct mock-Pi callback drivers, fake proof helpers, the old static/prose suite,
and five duplicate focused catalogs were removed. Historical receipts stay in
storage/Git; they are not current readiness evidence. Production validators and
execution guards were not relaxed or removed. The real feedback workflow exposed
one CLI defect: missing indexed search fields plus an any-hit recall check. The
CLI now uses indexed fields and the extension's bounded exact-key readback pattern.
The failing pre-fix receipts remain retained; assertions were not weakened.

Useful negative intent was moved to real workflow faults above. This is NOT
one large case secretly invoking the removed unit tests.

## Remaining proof limits

These cases do not establish every parser variation, every escalation provider,
interactive review-picker UX, debugger integration, OS tamper resistance, or
universal project completion. Historical shadow rows were not backfilled. Those
areas are unproven, not silently counted as
passing. A closed ticket or a smaller green suite is not global acceptance.

No tests should be added merely to inflate the count. Add a workflow only for a
specific failure or capability, with source-bound inputs and an effect that can
be independently checked. Provider failures remain failed/unestablished runs;
do not replace them with a mocked success.
