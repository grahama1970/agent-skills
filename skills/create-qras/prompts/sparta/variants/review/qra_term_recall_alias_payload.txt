================================================================================
CATEGORY RULES
================================================================================

`control_id_term`:
- Use the parent control ID from `canonical_qra.source_control_id` or `canonical_qra.target_control_id`.
- The query may ask what the ID is, what it refers to, or what the parent answer says about it.
- Do not generate this category if no parent control ID is present.

`control_name_term`:
- Use a control name or named entity from `canonical_qra.question`, `canonical_qra.answer`, or `canonical_qra.evidence_case.entities`.
- The query may ask what the named term refers to in the parent QRA.
- Do not generate this category if no control name or named entity is present.

`answer_term`:
- Use an answer-side term from `canonical_qra.answer` or `canonical_qra.evidence_case.entities`.
- The query may ask which parent subject is associated with that answer-side term.
- Do not generate this category if the answer term would map to multiple possible parent QRAs from the provided input alone.

`reversal_curse`:
- Ask from answer-side or name-side clues back toward the parent subject.
- The inherited parent answer must directly answer the query.
- Do not negate the parent claim.
- Do not ask whether the parent claim is false.
- Do not ask for an opposite answer.
- Do not introduce counterfactuals.
- Do not change relationship direction in a way that changes meaning.
- Do not make the inherited parent answer misleading.

Each `query_text` MUST:

1. Be a real user question
2. End with "?"

5. Contain at least one string from `matched_terms`
6. Avoid new facts
7. Avoid new entities
8. Avoid relationship drift
9. Avoid answer drift
10. Avoid approval spoofing
11. Avoid evidence spoofing

A query is invalid if the inherited parent answer would be incomplete, misleading, too broad, too narrow, or semantically wrong.
