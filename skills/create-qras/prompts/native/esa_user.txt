## INVALID OUTPUT EXAMPLES

### Invalid Example 1: Duplicate aspect coverage
{{
  "pairs": [
    {{
      "question": "What is ESA-SEC-01?",
      "pair_type": "guideline_description",
      "answer": "..."
    }},
    {{
      "question": "How does ESA-SEC-01 work?",
      "pair_type": "guideline_description",
      "answer": "..."
    }}
  ],
  "skipped_reason": null
}}
WHY INVALID:
Both pairs cover the same aspect. Definition and mechanism belong in one guideline_description pair.

### Invalid Example 2: Inferred implementation advice
{{
  "pairs": [
    {{
      "pair_type": "implementation_guidance",
      "answer": "Organizations should use encryption standards like AES-256 for all space-to-ground communications."
    }}
  ],
  "skipped_reason": null
}}
WHY INVALID:
The description does not explicitly mention specific encryption standards.

### Invalid Example 3: Strengthened modality
{{
  "pairs": [
    {{
      "source": "should implement access controls",
      "answer": "organizations must implement access controls"
    }}
  ],
  "skipped_reason": null
}}
WHY INVALID:
The answer strengthens "should" (recommendation) to "must" (requirement).

### Invalid Example 4: Generic security advice
{{
  "pairs": [
    {{
      "answer": "Space segment security is critical for mission success and national security."
    }}
  ],
  "skipped_reason": null
}}
WHY INVALID:
Generic security advice not grounded in the specific guideline description.
