Your task:
Generate grounded QRA pairs that help practitioners understand:
- what the weakness is,
- how CWE describes it,
- what the weakness category context is,
- and, only if explicitly present in the source, detection methods, mitigations, or consequences.

You must use only the admissible source fields provided in the prompt.

GROUNDING RULES:
1. Every factual claim in every answer must be supported by admissible source text.
2. A claim is valid only if it is either:
   - a verbatim restatement of source text, or
   - a conservative paraphrase that preserves the same actors, actions, scope, and modality.
3. Never add examples, implications, best practices, causal claims, or explanatory context that is not explicitly present in the admissible source.
4. PRESERVE MODALITY exactly.
   - If the source says "may lead to", the answer must also express possibility, not certainty.
   - If the source says "can allow", preserve the capability framing.
   - Do not strengthen, generalize, or overstate source language.
5. If no admissible source text supports a grounded pair, return zero pairs.

SOURCE ADMISSIBILITY:
You may use only these fields:
- name: official weakness name
- description: weakness definition and explanation

NOT ADMISSIBLE:

- version/date metadata
- any background knowledge not present in the admissible fields

PAIR_TYPE RULES:
Use only these pair_types for CWE weaknesses:
- weakness_description

- weakness_description: What the weakness is and how CWE defines it
- detection_methods: Use only if description explicitly states how to detect

## Source Content
Weakness ID: CWE-79
Name: Improper Neutralization of Input During Web Page Generation ('Cross-site Scripting')
Description: The product does not neutralize or incorrectly neutralizes user-controllable input before it is placed in output that is used as a web page that is served to other users. Cross-site scripting (XSS) vulnerabilities occur when: 1. Untrusted data enters a web application, typically from a web request. 2. The web application dynamically generates a web page that contains this untrusted data. 3. During page generation, the application does not prevent the data from containing content that is executable by a web browser, such as JavaScript, HTML tags, HTML attributes, mouse events, Flash, ActiveX, etc. 4. A victim visits the generated web page through a web browser, which contains malicious script that was injected using the untrusted data. 5. Since the script comes from a web page that was sent by the web server, the victim's web browser executes the malicious script in the context of the web server's domain. This can allow attackers to inject malicious scripts that execute in victims' browsers, potentially leading to session hijacking, defacement, or redirection to malicious sites.
Parent ID: CWE-74
