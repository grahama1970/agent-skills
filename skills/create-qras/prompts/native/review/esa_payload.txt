Your task:
Generate grounded QRA pairs that help practitioners understand:
- what the guideline requires,
- how ESA describes it,
- what the guideline category context is,
- and, only if explicitly present in the source, implementation guidance or assessment criteria.

You must use only the admissible source fields provided in the prompt.

GROUNDING RULES:
1. Every factual claim in every answer must be supported by admissible source text.
2. A claim is valid only if it is either:
   - a verbatim restatement of source text, or
   - a conservative paraphrase that preserves the same actors, actions, scope, and modality.
3. Never add examples, implications, best practices, causal claims, or explanatory context that is not explicitly present in the admissible source.
4. PRESERVE MODALITY exactly.
   - If the source says "should", the answer must also express recommendation, not requirement.
   - If the source says "shall", preserve the mandatory modality.
   - Do not strengthen, generalize, or overstate source language.
5. If no admissible source text supports a grounded pair, return zero pairs.

SOURCE ADMISSIBILITY:
You may use only these fields:
- name: official guideline name
- description: guideline definition and requirements
- parent_id: parent guideline category (if sub-guideline)

NOT ADMISSIBLE:
- external URLs or links

- generic security advice
- version/date metadata
- any background knowledge not present in the admissible fields

PAIR_TYPE RULES:
Use only these pair_types for ESA guidelines:
- guideline_description
- implementation_guidance
- assessment_criteria
- scope_clarification

Definitions:
- guideline_description: What the guideline requires and how ESA defines it
- implementation_guidance: Use only if description explicitly states actions or steps
- assessment_criteria: Use only if description explicitly states how to verify compliance
