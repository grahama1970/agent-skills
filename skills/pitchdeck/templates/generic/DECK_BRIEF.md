# Deck brief

## Audience

Name the exact reader and decision context.

## Deck job

State the one action the presentation should earn: design-partner conversation,
technical evaluation, pilot approval, funding discussion, or another bounded outcome.

## Narrative

```text
problem -> insight -> product -> demonstration -> differentiation -> proof -> honest gaps -> ask
```

## Required boundaries

- README prose remains source material, not automatic proof.
- Public slides may use only explicitly public sources and assets.
- Status and proof claims require dates, populations, scope, and qualifiers.
- Missing or stale visual evidence remains visible.
- The final slide carries the project’s mandatory non-claims.

## Visual acceptance

- 16:9 layout.
- One primary message per slide.
- Native text and shapes remain editable.
- Screenshots fit without cropping meaning-bearing content.
- Narrative text remains at least 12 pt; target 16–28 pt.
- Contact-sheet review occurs before external use.
