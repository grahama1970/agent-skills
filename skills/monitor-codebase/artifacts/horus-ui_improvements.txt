## Codex Technical Overview
**Scope**
“Fix common violations” in a Python project is best treated as an engineering system, not a one-off cleanup. The winning pattern is: `detect -> auto-fix -> verify -> prevent regression`.

**Violation Taxonomy**
1. Formatting/import hygiene: inconsistent style, import order drift, dead imports.
2. Static correctness: type errors, unreachable code, undefined names, bad exception handling.
3. Architecture violations: circular dependencies, boundary leakage, God modules, hidden side effects.
4. Reliability: flaky tests, weak assertions, missing edge-case tests.
5. Security/supply-chain: vulnerable deps, unsafe deserialization, subprocess misuse, secret leakage.
6. Packaging/runtime: implicit deps, lock drift, non-reproducible environments.

**Architecture Pattern (What scales)**
1. Single source of truth in `pyproject.toml` for lint/type/test tool config.
2. Layered quality gates:
   1. Local fast gate: formatter + linter auto-fix + import cleanup.
   2. Pre-commit gate: deterministic checks on changed files.
   3. CI full gate: strict type checking, full tests, security scans.
3. Deterministic fixer order to avoid tool fights:
   1. Formatter
   2. Import/unused cleanup
   3. Lint auto-fixes
   4. Type check
   5. Tests
4. “No new debt” policy: block only new violations first, then burn down baseline.
5. Ownership model: each package/module has explicit owner + quality budget.

**Common Pitfalls**
1. Tool overlap conflicts (multiple tools rewriting imports/formatting differently).
2. Turning on strict typing globally in one shot and drowning in noise.
3. Using broad ignore lists that hide real defects.
4. Over-indexing style fixes while correctness/security regressions remain.
5. Non-deterministic CI (different Python/tool versions locally vs CI).
6. Big-bang refactors without characterization tests, causing behavior drift.
7. Weak exception policies (`except Exception: pass`) masking production faults.

**State-of-the-Art Approaches**
1. Consolidated, high-performance linting/auto-fix pipelines (modern single-tool-first strategies) to reduce latency and config complexity.
2. Incremental strict typing:
   1. Public interfaces first
   2. Domain/core next
   3. Peripheral adapters last
3. Policy-as-code for architecture rules (forbidden imports, layer boundaries, dependency direction checks).
4. AST/CST codemods for safe large-scale fixes (instead of regex edits).
5. Risk-based quality gates:
   1. Always gate correctness/security
   2. Soft-gate style during migration
6. Supply-chain hardening:
   1. Pinned lockfiles
   2. Vulnerability scanning in CI
   3. SBOM/provenance where required
7. AI-assisted remediation with deterministic validation loops:
   1. AI proposes patch
   2. Automated checks verify
   3. Reject if checks fail

**Practical Rollout**
1. Week 1: establish baseline metrics, freeze toolchain versions, enable fast local auto-fix.
2. Week 2: enforce “no new violations” in CI on changed files.
3. Week 3-4: tighten type/security gates per module priority.
4. Ongoing: track violation burn-down and mean time to remediation.
