## Codex Technical Overview
**Interpretation**
`handwritten-tests(21)` usually means your project has 21 tests flagged as ad-hoc/manual-pattern tests: duplicated setup, brittle assertions, and low reuse of shared test infrastructure.

**Architectural Pattern To Fix It**
1. Centralize test construction:
- Move object creation into factories/builders (`tests/factories.py`).
- Move environment/bootstrap into layered fixtures (`session` for global, `function` for isolation).

2. Separate test intent from mechanics:
- Keep test bodies focused on behavior.
- Push heavy setup, mocks, and wiring into helpers/fixtures.

3. Use typed, composable test utilities:
- Shared helpers with explicit types (no untyped dict blobs).
- Small assertion helpers for domain semantics (not repeated raw `assert x == y` chains).

4. Introduce test taxonomy:
- Unit tests: pure logic, no I/O.
- Contract tests: API/schema boundary.
- Integration tests: DB/network with controlled fixtures.
- E2E only for critical flows.

**Common Pitfalls**
- Over-mocking internals, then breaking tests during refactor without behavior changes.
- Fixture sprawl (`conftest.py` god-file) causing hidden coupling.
- Non-determinism (time, randomness, network, shared temp dirs).
- Snapshot abuse without semantic assertions.
- Repeated Arrange logic across files instead of reusable factories.
- Tests asserting implementation details instead of public behavior.

**State-of-the-Art Practices**
- Property-based testing (`hypothesis`) for invariants and edge exploration.
- Mutation testing (`mutmut`, `cosmic-ray`) to detect weak assertions.
- Contract/schema testing (OpenAPI/JSON Schema/Pydantic model contracts).
- Flake detection and quarantine pipeline (rerun + statistical flakiness scoring).
- Deterministic clocks/seeds and hermetic test environments (containerized dependencies).
- Coverage quality over raw percentage: branch coverage + mutation score + critical-path coverage.

**Practical Remediation Plan For 21 Violations**

- nondeterministic behavior

2. Build shared primitives first:

3. Refactor tests in batches by module, not one-off.

4. Add guardrails:
- lint rules for test anti-patterns
- CI gate for flaky tests
- mutation threshold for critical packages

5. Track outcome metrics:
- flake rate
- median test runtime
- mutation score
