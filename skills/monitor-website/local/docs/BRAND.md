# monitor-website local brand guard — grahama.co

This is the operational brand guard for `$monitor-website`. It repeats the parts
of `site/BRAND.md` that matter during audits, updates, plans, and repair loops
so a maintenance agent does not flatten grahama.co into category marketing.

Canonical brand source: `site/BRAND.md`.
Canonical design source: `site/DESIGN.md`.

## 1. Operating premise

grahama.co should be discovered, not optimized into a cold value proposition. It
should be bespoke, entertaining, honest, strange, source-backed, and
unmistakably Graham. It should not look like any other AI/R&D-tech site.

The site is allowed to be dense, nonlinear, weird, and personal. It is not
allowed to be stale, fake, inaccessible, or imprecise.

## 2. What to protect

Protect these brand truths during every monitor-website action:

- first-person singular Graham voice;
- the unusual career arc: composer, Sony producer, DARPA technical lead, formal
  methods, agent systems;
- the collision of creative work and technical proof;
- visible proof boundaries;
- project source trails;
- public/private evidence distinctions;
- Dream, voice, media, and other strange work as serious parts of the practice;
- dark editorial artifact-room tone unless Graham explicitly changes it.

## 3. What to repair

`$monitor-website` may repair defects that make the weirdness look accidental:

- README/content/inventory drift;
- stale generated surfaces;
- wrong canonical repository links;
- wrapper links presented as system repos;
- missing skill-contract secondary links;
- missing `alt`, `aria-label`, `data-qid`, or `data-qs-action`;
- stale proof displays;
- overclaimed generated media;
- unclear private/public evidence boundaries;
- broken discovery paths.

These repairs strengthen the brand because they keep the facts exact.

## 4. What not to repair away

Do not treat these as defects by default:

- density;
- mystery;
- nonlinear navigation;
- odd labels;
- artifacts that require inspection;
- Dream or creative work appearing near defense/compliance systems;
- first-person weirdness;
- refusal to become a normal services page.

Treat unusualness as intentional unless current evidence proves a factual,
accessibility, provenance, or broken-path problem.

## 5. Anti-category rejection list

Reject plans whose main effect is to make grahama.co more like:

- Straive-style offshore AI services;
- Palantir-style defense/sovereign operating-system grandeur;
- generic R&D-tech innovation lab;
- AI consultancy value proposition;
- SaaS startup homepage;
- service/industry/contact funnel.

Forbidden phrases and frames unless directly quoted as anti-examples:

- "AI operationalization";
- "industry-leading";
- "world-class";
- "seamless transformation";
- "business outcomes" as the main proof;
- "our services" as the site spine.

## 6. Required evidence posture

When `$monitor-website` reports on grahama.co:

- label proof boundaries;
- use Surf before browser-visible visual judgments when Surf is available;
- distinguish current evidence from historical context;
- cite changed files and validation commands;
- never claim a visual/design change is ready from prose confidence;
- never use a green self-authored check as proof of live deployed behavior.

## 7. Brand review checklist

Before applying or recommending a change, answer:

1. Does this make grahama.co more Graham?
2. Does it preserve discovery?
3. Does it avoid R&D-tech mimicry?
4. Does it keep facts exact?
5. Does it improve a real defect rather than flattening taste?
6. Does it preserve entertaining strangeness?
7. Does it keep creative and technical work equally serious?

If any answer is no, return a targeted alternative instead of applying the
change.
