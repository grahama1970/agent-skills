The pipeline reliability story is now strong (five unattended cycles, re-driving boundary checker, four adversarial rounds with fixture-proven fixes) — but reliability is the precondition for the research claim, not the claim. "Dreams as affect engine" becomes credible only when three things are separately measurable: (1) fidelity — the dream's content is entailed by the agent's actual residue (grounding 1.0 is a start, but it measures citation coverage, not selective emphasis: an accurate-but-affectless summary would also score 1.0); (2) transfer — the ToM→voice derivation carries dream-specific signal, testable by ablation: same residue, dream phase replaced by a neutral summarizer, does the derived profile differ, and in the direction the dream's conflict content predicts?; (3) perceptibility — question (c). The needed instruments, in fixture terms: a frozen affect-annotation schema applied to dream content pre-derivation (so "the dream contains conflict about kai-age15" is a committed label, not a post-hoc reading), and a pre-registered directional hypothesis per cycle ("this dream should lower temperature and slow pace on kai-adjacent topics") frozen before voice derivation runs — the exact analogue of the content-matched recall instruments frozen pre-dream in V2/V3. Baselines: (i) no-dream flat profile, (ii) residue-summary-derived profile (no dream phase), (iii) shuffled-dream profile (wrong dream's weights on this persona) — (iii) is the killer ablation because it distinguishes "dreams add affect" from "dreams add this persona's affect." (b) Composition and consumption contract. Freeze the contract before writing the composer, because this is exactly where the References-rollback pattern recurs: composition logic is a document-context pass over per-dream page-local outputs, and letting it mutate stored per-dream profiles would repeat the mistake. Concrete contract: per-dream profiles are immutable, versioned artifacts (hash-bound, as ToM payloads already are); composition is a pure, deterministic function over the set of active profiles plus a conversation-context vector, producing a per-turn tone tag bundle. On the composition function itself: recency decay alone is wrong for an affect engine — a founding dream (Kling) should not decay to zero; use a two-term model: a slow-moving persona-state prior (intensity-weighted running composition, updated only at dream activation, edge-closure-gated like everything else) plus topic-conditional activation (per-turn boost when conversation embedding matches a dream's committed theme signature, with a hard counterpart gate reusing the existing Brandon/Kai fixture logic — topic activation must never fire a dream onto its non-counterpart). Consumption contract for chatterbox: persistent persona-state vector as the default, per-turn tags as deltas — per-turn-only makes affect flicker turn-to-turn and is unauditable; state-vector-only can't respond to topic touches. The delta form also makes every turn diffable: log (prior, activation, delta, final tags) so any rendered turn is reproducible from committed artifacts, matching the boundary checker's re-derivation discipline. (c) Perceptibility measurement. The A/B-same-text design is right and should be the primary endpoint: identical reply text synthesized under (dream-weights vs flat vs shuffled-dream), evaluated two ways. Objective: prosody deltas (F0 mean/range, speech rate, pause distribution, energy) must first show the weights reach the waveform — if prosody doesn't move, listener eval is moot; this is a cheap automated gate runnable every cycle. Perceptual: forced-choice listener eval ("which rendition sounds more [committed affect label]?") with the label drawn from the pre-registered hypothesis, not chosen after listening. Fixture-discipline addition: make one A/B triplet per dream cycle a pinned regression artifact — synthesized audio hashes committed at activation — so affect drift (d, risk 1) is detectable as a diff, not an impression. (d) Top 3 risks and cheapest guards. (1) Affect drift / runaway accumulation: composition over many dreams walks the persona-state vector monotonically (e.g., ever-darker). Cheapest guard: hard bounds on the state vector plus a per-activation max-delta gate (a single dream may move any dimension at most ε), fail-closed like edge-closure — this is a numeric invariant, trivially fixture-testable. (2) Wrong-counterpart contamination at composition time: the structural block covers dream generation; composition and topic-activation are a new leak surface (kai-age15 themes activating on adult-kai conversation is the live near-miss class). Guard: counterpart hard-gate re-asserted inside the composer with the existing leak fixture ported to composition inputs, plus a live negative case per persona pair in the boundary checker's re-drive. (3) Over-smoothing: averaging N profiles converges to bland mid-range affect, destroying exactly the nuance-and-conflict signal the operator wants. Guard: don't average — compose by dominant-activation with bounded blend (top-k activated dreams, k≤2, weighted by activation margin), and add a variance floor to the perceptibility gate: composed output must remain distinguishable from the flat baseline in the prosody metrics, or the composition (not the dreams) fails the gate. Ranked recommendations: Freeze the composition contract now (immutable per-dream profiles; pure deterministic composer; logged prior/activation/delta/final per turn) before any composer code lands. Add the shuffled-dream ablation to the next cycle — it is the single cheapest experiment that converts pipeline reliability into a research claim. Pre-register a directional affect hypothesis per dream (frozen pre-derivation, same discipline as the recall instruments) and score every cycle against it. Port the counterpart hard-gate and leak fixture into the composer/topic-activation path with live negative cases in the boundary checker re-drive. Pin one A/B prosody triplet per cycle as a hash-committed regression artifact with a max-delta bound on the persona-state vector — drift becomes a failing diff, not a vibe. Evidence The strongest evidence that contract-first is the right move is this project's own history: the Brandon-roots/Kai-targets leak was caught at a cross-context boundary (roots from one cluster, targets from another) — composition across dreams is structurally the same boundary class, multiplied. The V2 measurement-amendment lineage (v1–v1.5) and the frozen protocol v3 NULL result show the team already knows how to pre-register and report honestly; extending that discipline to affect hypotheses is incremental, not new machinery. Grounding=1.0 as currently computed is citation coverage, which cannot distinguish affect-bearing from affect-neutral renderings of the same residue — hence the need for the summarizer and shuffled ablations. The re-driving boundary checker (live probe reruns, hash-bound receipts, recomputed payload hashes) is the template the composer must match: everything it consumes already exists as hash-committed artifacts, so the pure-function contract costs little. Uncertainties Whether chatterbox's /synthesize surface can consume a state-vector-plus-delta contract per turn or only flat tags — if only tags, the composer must flatten at the boundary and the delta log becomes external. Whether five clusters give enough dream diversity for the shuffled-dream ablation to be meaningful (shuffling among similar-affect dreams under-tests it; kai vs kai-age15 may be too correlated — prefer shuffling across maximally distant pairs, e.g., marketa↔tommy). Whether listener-eval capacity exists in the loop; if not, the objective prosody gate must carry perceptibility alone for now, which measures acoustic difference, not perceived affect — a real but acceptable gap to flag. Round-5 verification is pending; everything above assumes it lands without structural findings. Blockers None hard today, but three ordering constraints: no composer code before the frozen contract artifact exists (recommendation 1); no multi-dream activation in live chatterbox until the composition-path counterpart fixtures pass (recommendation 4); and no "affect engine" research language in any external claim until at least one cycle has passed the pre-registered directional test against both baselines — the same standard that kept the C-vs-F NULL honest.
