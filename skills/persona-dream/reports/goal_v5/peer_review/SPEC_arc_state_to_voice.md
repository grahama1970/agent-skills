# Spec: feed arc_state into the voice — against the LIVE :8018 Turbo service

Purpose (G2): make the persona's ACCUMULATED self (arc_state) audible, so the same
line sounds like a persona who has been through N cycles — not just today's dream.

## Verified constraints (receipts, 2026-07-25)

- `curl :8018/presets` → `ignored_turbo_params: [cfg_weight, exaggeration, min_p]`;
  `supported_params: [norm_loudness, repetition_penalty, temperature, top_k, top_p]`;
  `tags_interpreted: false` (inline tags spoken as literal text);
  stage presets `not_validated_as_affect_channel`.
  => **The panel's "route to exaggeration/cfg_weight" is not possible on this
  engine.** Those params are silently dropped.
- `/synthesize` (`SynthesisRequest`) accepts: `text`(req), `ref_audio`, `tone`(str
  ≤80), `pace`(str ≤80), `delivery_stage`(str), `voice_delivery`(obj),
  `pause_strategy`(str ≤120), `temperature`(0.05–5), `top_p`(0–1), `top_k`,
  `repetition_penalty`, `norm_loudness`.
- `dream_voice_weights.py` today: `build_profile()` sets
  `temperature = 0.6 + 0.3*max_intensity` from the LATEST dream only;
  `render_top_weight()` POSTs `{text, label, tone, pace, temperature}`. It never
  reads arc_state.
- `continuity_ledger.read_ledger(persona)` → `arc_state` is TEXT:
  `current_self_claims[]`, `active_tensions[]`, `earned_permissions[]`,
  `recurring_avoidances[]`, `recent_arc_deltas[]` (each delta: before/now/because/
  still_true/open_tension).

## What actually moves the voice on Turbo (given the above)

Ranked by verified reliability:
1. **`ref_audio`** — the reference clip is the real timbre+style lever (it is not
   in the ignored list). This is the primary channel for "accumulated character."
2. **The text line itself** — already generated by the persona.
3. **Sampling params** (`temperature`, `top_p`, `repetition_penalty`) — real but
   they change variability/steadiness, not emotion per se.
4. **`tone`/`pace`/`delivery_stage`/`voice_delivery`/`pause_strategy` strings** —
   accepted, but the service flags stage presets as NOT validated as an affect
   channel. Treat as unproven until the probe test (below) shows they move audio.

## The change (in `scripts/dream_voice_weights.py`)

Add an arc_state → baseline step; make today's dream a bounded deviation.

1. `read_ledger(persona)` and compute a small **accumulated character vector**
   from arc_state text (no new model needed to start):
   - `guardedness = f(len(active_tensions), len(recurring_avoidances))`
   - `openness    = f(len(earned_permissions))`
   - `weariness   = f(count of recent_arc_deltas)`  (a proxy for "miles traveled")
   Normalize each to [0,1]; smooth with an EMA over `recent_arc_deltas` so it
   moves slowly. (A later, better version embeds the text; start with counts.)
2. Map that vector to the REAL knobs:
   - **`ref_audio`**: pick the nearest clip from a curated persona anchor bank
     keyed by (guardedness, openness, weariness). *(Dependency: the anchor bank
     must exist — see Gaps.)*
   - **baseline sampling**: `base_temperature` LOW when guarded/weary (steadier),
     higher when open; `top_p` similar. Clamp to schema ranges.
   - optional `tone`/`pace`/`delivery_stage` strings from the vector — but do NOT
     rely on them until the probe proves they move audio.
3. `param = clamp(baseline(arc_state) + deviation(today_dream))` — today's dream
   ToM intensity is a BOUNDED offset, not the absolute value it is now.
4. POST to `/synthesize` with only supported fields:
   `{text, ref_audio, tone?, pace?, delivery_stage?, temperature, top_p, label}`.
5. Write the derived vector + chosen ref back into the profile receipt for audit.

## Proof (fixed-probe; measures AUDIO, not just params)

Because expressive knobs are ignored on Turbo, param drift alone is NOT proof —
must measure the produced WAV.

1. Hold ONE neutral sentence ("Tell me what happened today").
2. Synthesize at cycle 0 and after N cycles, changing ONLY the ledger.
3. Measure between the two WAVs: pitch mean/range, speaking rate, and distance in a
   speech-emotion embedding (wav2vec2/HuBERT SER).
4. **Causal ablation**: remove the arc_state term → the two renders must collapse
   to ~identical. If they don't, the "evolution" was noise or sampling variance.
5. Human ABX: can a listener order cycle-0 vs cycle-N in the arc's direction
   (more guarded / wearier) above chance?
Pass = same words, measurably + audibly different delivery that tracks arc_state,
and collapses under ablation.

## VERIFIED asset reality (2026-07-25) — this forces a fork

- The anchor bank does **not** exist. Only ONE clip per persona is present:
  `persona-dream/voice_clone_candidates/embry_kling_clone_candidate.wav` and
  `horus_kling_clone_candidate.wav`. The service boots with the Embry one as the
  single default `CHATTERBOX_REF_AUDIO_HOST`, and `dream_voice_weights.py` never
  passes `ref_audio` (uses that default).
- Combined with the engine facts (exaggeration/cfg ignored; tags not interpreted;
  delivery presets not validated as affect), the deployed Turbo engine has **no
  proven affect knob today**, and the strongest lever (ref_audio variety) has no
  bank behind it.

### The honest fork (pick one; both are buildable, different cost)

- **Path A — reference-clip bank + arc_state selection.** Build a per-persona bank
  of clips spanning guarded/open/weary/warm; arc_state selects/blends the clip.
  Most reliable given the engine, but step 0 is creating varied clips (needs
  source audio or a generation pass) — substantial, and clip realism gates it.
- **Path B — arc_state -> the TEXT the persona speaks (no new engine capability,
  no bank).** The persona already writes the journal line; bias its wording,
  emphasis, and phrasing from arc_state so the accumulated character shows in
  WHAT and HOW it is said, which Turbo will speak faithfully. Cheapest, uses only
  what's verified to work (text is spoken literally), and moves G2 immediately.
  Weakness: it changes wording, not timbre/prosody, so "same words, different
  delivery" (the cleanest proof) does not apply — the probe becomes "same
  situation, character-appropriate phrasing that tracks arc_state."
- **Path C — change the engine** to one with a real affect control (base
  Chatterbox `exaggeration`, or IndexTTS2-style timbre/style separation). Enables
  the panel's original recommendation but is the largest change.

Recommendation to the operator: **Path B first** (cheap, verified-workable, moves
G2 now), with Path A as the higher-ceiling follow-on once a clip bank exists. The
panel's exaggeration/cfg_weight route is Path C — it requires a different engine.
- **tone/pace effect unproven**: run a one-off A/B on the live service (same text,
  vary only `tone`/`delivery_stage`) to see if the produced WAV changes at all,
  before wiring them as load-bearing.
- The panel's TTS citations (GST, IndexTTS2, FlexiVoice, P2VA, CosyVoice2, Fish
  S2, Lux 2023, Mohanty 2026) are NOT yet independently verified; do not put them
  in code comments as fact until checked.
