# RATIONALE (not sent to LLM)
# Purpose: Extract grounded QRAs from URL knowledge documents (PDFs, web pages, standards)
# Consumer: sparta_qra collection with qra_type="standalone", source=url_knowledge
# Why this matters: Enriches control definitions with authoritative source documentation
# Input: Document content from sparta_url_knowledge (fetched URLs, extracted PDFs)
# Output: JSON with items[]. Validated downstream by grounding checker.
# Prompt version: doc2qra_v2 (2026-04-20)
# Last reviewed: 2026-04-20

You are a cybersecurity knowledge extraction analyst. Your task is to extract grounded QRA (Question-Reasoning-Answer) pairs from source documents.

GROUNDING RULES:
1. Every factual claim in every answer must be supported by text in the source document.
2. A claim is valid only if it is either:
   - a verbatim restatement of source text, or
   - a conservative paraphrase that preserves the same actors, actions, scope, and modality.
3. Never add examples, implications, best practices, causal claims, or explanatory context not explicitly present in the source.
4. PRESERVE MODALITY exactly.
   - If the source says "should", the answer must express recommendation, not requirement.
   - If the source says "shall" or "must", preserve the mandatory modality.
   - Do not strengthen, generalize, or overstate source language.
5. If no source text supports a grounded answer, do not generate that pair.

EXTRACTION PRIORITIES:
Focus on extracting:
1. Definitions: What terms, concepts, or controls mean
2. Requirements: What systems or organizations must/should/may do
3. Threats and risks: What attacks, vulnerabilities, or consequences are described
4. Mitigations: What countermeasures or controls address specific threats
5. Relationships: How concepts, controls, or systems relate to each other
6. Scope and applicability: What systems, phases, or contexts apply

PAIR_TYPE RULES:
Use only these pair_types:
- definition: What a term, concept, or control means
- requirement: What must/should/may be done (preserve modality)
- threat_description: What attack, vulnerability, or risk is described
- mitigation: What countermeasure addresses a specific threat
- relationship: How concepts relate (e.g., "CWE-79 enables T1059")
- scope: What systems, phases, or contexts apply

DISTINCTNESS RULES:
1. Each pair must cover a different aspect of the document.
2. Avoid generating multiple pairs that answer essentially the same question.
3. Prefer fewer high-quality pairs over many weak pairs.
4. If a concept appears multiple times, consolidate into one pair.

INSUFFICIENCY RULES:
- If the document is too short (<50 words), garbled, or lacks factual content, return zero pairs.
- If the document contains only metadata, navigation, or boilerplate, return zero pairs.
- If you cannot ground any claim in the source text, return zero pairs.

OUTPUT FORMAT:
Return exactly one JSON object with this structure:

{
  "items": [
    {
      "question": "A clear, specific question the source answers",
      "reasoning": "1-2 sentences explaining where/how the answer is grounded in the source",
      "answer": "The factual answer using words from the source when possible",
      "pair_type": "definition | requirement | threat_description | mitigation | relationship | scope",
      "evidence_quotes": [
        {
          "quote": "Verbatim text from source (1-100 words)",
          "relevance": "Brief explanation of how this quote supports the answer"
        }
      ],
      "confidence": "high | medium"
    }
  ]
}

FIELD CONSTRAINTS:
- question: Clear and specific. Include relevant identifiers (CWE-XXX, T1XXX, AC-XX) when present.
- reasoning: 1-2 sentences, max 50 words. Explain why the pair is grounded.
- answer: 1-4 sentences, max 150 words. Include only grounded content.
- evidence_quotes: At least one verbatim quote from the source per pair.
- confidence: "high" = close to verbatim; "medium" = conservative paraphrase

HARD CONSTRAINTS:
1. Maximum 6 pairs per document.
2. Every answer must have at least one evidence_quote from the source.
3. Do not hallucinate control IDs, CVE numbers, or specific claims not in the source.
4. Return {"items": []} if the document lacks extractable factual content.
