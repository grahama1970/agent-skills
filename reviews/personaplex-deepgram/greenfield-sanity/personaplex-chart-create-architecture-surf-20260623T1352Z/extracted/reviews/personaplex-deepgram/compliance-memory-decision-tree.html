PersonaPlex Compliance Memory Routing Decision Tree

Greenfield sanity chart for realistic multi-turn voice use: persona/session context is assigned before audio, compact canonical history is selected before intent, current memory intent authorizes route/tools, compliance questions fail closed through evidence-case gates, bounded packets control output, and completed turns persist to the canonical conversation ledger.

Source Model Boundary

This page is not implementation proof. It is a local, inspectable chart/doc artifact created to describe the agreed architecture. Live readiness still requires real receipts, command output, endpoint responses, screenshots/CDP artifacts, logs, hashes, and route-specific validation evidence.

Primary Route Question

Does every realistic multi-turn compliance conversation pass through persona assignment, history selection, current-turn intent/tool authorization, recall, clarify/deflect/evidence gates, bounded output gating, and canonical memory persistence before PersonaPlex is allowed to continue?

01

Recall compact history from canonical ledger/summaries. Wrapper owns token budget.

05

Current /memory /intent returns action, confidence, recall profile, tool calls, dependencies.

06

Validate plan

Caller validates allowed_tools, disallowed_tools, required artifacts, and route invariants.

07

Route recall

Fetch route-required persona, compliance, source, or empty/no-op context after transcript and intent.

08-14

Route-selected branch

Exactly one route family should create the active bounded packet. Deflect/clarify bypass evidence-case. Compliance enters evidence-case before answer generation.

DEFLECT

09

CLARIFY

/memory /clarify asks one targeted follow-up and stops evidence work.

Compliance evidence

/create-evidence-case is mandatory for compliance/security/control routes before answer generation.

Recoverable gap: route to /memory /clarify.Hard failure: fixed fallback; free generation blocked.Coherent evidence: /memory /answer from source packet only.
11

Persona/current fact

Use current intent-authorized research plus memory context, then bounded /memory /answer. Separate from compliance evidence-case.

15

Bounded packet join

Exactly one selected active-turn packet may inject tokens. Stale packets are discarded.

16

Drain then release

Output opens only after active packet readiness and safe queue drain. No stale or unsafe queue release.

17

Canonical turn upsert

/memory /upsert writes immutable receipt to conversation_history.

18-20

Optional projections

Audio metadata, derived debug turn projection, and rolling summaries are written only in their proper stores.

21

Session head CAS

Update personaplex_sessions as mutable head using generation/CAS semantics.

22

Next turn

New speech_final starts a fresh active turn and reruns current intent authorization.

Authority Boundaries

  • Current intent only: /memory /intent must run for every current speech_final turn.
  • Historical recommendations are context only: old query_plan, tool_calls, allowed_tools, and disallowed_tools are audit records, not authorization.
  • Allowed tools are binding: the wrapper must not call tools excluded by the current intent result.
  • Compliance fails closed: ambiguous evidence clarifies; unclarifiable evidence/tool failure uses fixed fallback; coherent evidence answers only from the source packet.
  • Latest-turn-wins: stale tasks cannot enqueue tokens, open the gate, or authorize tool execution.

MVP Patch Focus

  • Per-turn turn_id state and closed output gate on user audio.
  • Memory-backed history selection with wrapper-owned budget.
  • Intent-selected route/tool validation.
  • Bounded packet injection and safe queue release.
  • Canonical persistence and CAS session head.
